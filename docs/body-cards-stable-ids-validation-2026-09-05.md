- `npm run build`：TypeScript 检查与生产构建通过。

## 规模夹具

Node 测试使用同一份 1,000 篇材料、100 个标签节点和 10,000 条历史事件。该结果用于比较代码路径，不代表所有手机的绝对速度。

| 路径 | 本次耗时 |
| --- | ---: |
| 重复整理前的冷缓存 | 38.3 ms |
| 重复整理的热缓存 | 22.2 ms |
| 主页 100 节点逐次预处理 | 1252.4 ms |
| 主页共享一次预处理 | 70.9 ms |
| 建立开始队列 | 26.9 ms |
| 挖空文本揭示 10,000 次 | 7.3 ms |
| FSRS 评分计算 1,000 次 | 7.1 ms |

热缓存第二轮没有再次调用解析器；只修改第 318 篇后，解析调用从 1,000 增加到 1,001。

## 隔离 Obsidian 验证

环境为 macOS、Obsidian 1.13.7、独立临时知识库，含 1,000 篇既有合成材料和新增混排笔记。

- 混排笔记识别为 6 张卡：标准问答 1、简写问答 1、独立挖空 2、标准挖空 1、旧问答 1。问答内 `c9`、代码 `c7`、属性 `c8` 和注释 `c6` 均未生成卡片。
- 首次补写 4 个正文隐藏 ID；旧 `^rv-legacy` 与 `<!--ID: 1700000000000-->` 保持原样。标准挖空的 Extra 正确保留。
- 首轮整理 967.2 ms；补写 ID 后共发生 1002 次缓存查询。第二轮 391.0 ms，1001 篇全部命中。修改一篇后 372.4 ms，1000 篇命中、1 篇重解析。清空缓存后正常重建；文件改名后 1001 篇全部命中。
- 清空缓存和改名后，测试来源的卡片 ID、排程和队列完全一致。
- 实际点击“制卡”可选择标准问答或标准挖空；“问答”插入正文 `Q:/A:`；“填空”直接包裹选中文字。三次制卡新增 3 张卡，只执行 1 次当前来源刷新，整库扫描为 0。选择简写问答答案后点击填空会拒绝，并保留原文。
- 无提示挖空显示为 70.8 px 宽的实线横线。揭示后答案出现在原句位置，题面只出现一次，Extra 位于“补充”区域。揭示阶段没有读取历史或来源；点击评分时重新读取正式历史和当前来源，写入评分事件并增加修订号。
- 首页按钮顺序为“整理数据、开始、统计、设置”。已确定合并结果的同步冲突不会形成首页待处理提示。

## 布局边界

桌面宽度和 390 × 844 窄屏均检查了主页、标准卡选择弹窗、隐藏挖空、揭示答案、Extra 和四个评分按钮，没有横向溢出。三个笔记页制卡按钮实测高度均为 44 px。

本次没有使用实体手机，也没有验证真实手机软键盘、手机系统资源限制或第三方同步服务的到达延迟；手机结论仅限 Obsidian 桌面端的 390 px 布局和共享代码路径。
