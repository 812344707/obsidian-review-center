## 实际 Obsidian 验收

使用两个独立临时知识库和独立应用配置，在 macOS 的 Obsidian **1.13.7** 中执行。每次自动操作先核对真实知识库路径，未接触用户正式知识库。

新安装流程共完成 46 条验收断言（包含优化任务完成检查）：

- 主页实际“整理数据”创建笔记和正文卡片；笔记与知识点的标签、数量和进度独立。
- 三个设置分类实际显示；输入、草稿切换、保存、错误后按钮恢复、显示开关及重载通过。
- 原生设置搜索能找到“备份”；切换分类后焦点留在新渲染的标签上。
- 实际笔记评分显示 `1／2／3／14 天`；原生 Auto-reveal 已开启。评分、撤销、移动原文和再次评分保留稳定身份。
- 实际卡片揭示、评分、撤销以及完整备份恢复通过；重载后记录和历史一致。
- 实际 Web Worker 完成笔记优化、模拟、采用建议、取消与草稿保存；合成训练数据未进入知识库正式记录。
- 注入损坏排程后，读取停止并报告具体文件；坏文件、原文和历史均未被替换。恢复原内容后读取正常。
- 首次写入 `review_id` 后，人为维持该文件元数据缓存不可用；单次整理仍保留标签并创建两张卡片，修复此前漏识别问题。
- 关闭插件后等待延迟回调结束，评分栏不会重新出现；最终程序重新启用后进度保持一致。

没有未捕获的页面错误。控制台仅出现故意注入损坏排程时的预期诊断。[完整原生验收结果](assets/1.0.0-native-qa.json)

## 0.4.6 → 1.0.0 升级

先在独立应用中运行 0.4.6，建立两篇笔记、三张卡片，实际保存一条笔记评分和一条卡片评分，保留未完成队列；退出应用，逐文件更新程序，再启动 1.0.0。

8 条升级验收断言通过：设置语义、来源／卡片编号、状态、排程、历史与原文保持一致；4 个已有配置／数据文件的 SHA-256 未变。旧临时队列按设计不迁入，点击“开始”能依据原有排程重建剩余队列，新设置页正常。[升级结果](assets/1.0.0-upgrade-qa.json)

测试过程中还发现了首次写入编号使索引暂时失效的问题：旧版本首次只识别一张卡，重复整理才得到三张。新增回归测试先复现失败，再在最终候选中通过自动测试和原生应用故障注入验证。
